> 2026-10-06 与用户头脑风暴定稿。**定位：agent 市场化试点项目**——不是自用工具，
> 要的是能拿出手的完整闭环 + 差异化能力。派活前先看这里。
> 已定的 8 条技术决定（见 AGENTS.md 第二节）仍然全部有效，本文件不推翻任何一条。

## 定位对优先级的影响

- ✅ 优先：完整可演示的闭环、差异化能力（问账、自进化）、市场化的门面（报表/提醒）
- ❌ 砍掉：与 Obsidian 个人记账体系的打通（那是自用思路，与试点定位不符）

## P1 — 差异化能力（试点的卖点）

| # | 功能 | 说明 |
|---|---|---|
| P1-a | **自然语言问账** | 「这个月花了多少」「星巴克花了几次」。契约候选能力里已有 `bookkeeping.ledger.query`；路由 single_tool_action 直答 + 查账 handler（复式查询在 core/ledger 已有底子） |
| P1-b | **月度报表 + 超预算提醒** | 月度收支总览、分类占比；预算线提醒（餐饮 ≤1100 这类，预算值做成用户可配数据——仍是「分类是数据」的路子） |
| P1-c | **陌生商户批量归类** | 约定 7 明写：一次批量调用，不是 N 个任务。流水导入后把陌生商户列表发给调度层归类 |
| P1-d | **退款/状态变化冲减** | mimo 报的 API 缺口：`statusChanged` 只能看不能导入。数据层补形状（负向金额或冲减标记），界面给勾选入口 |
| P1-e | **日程领域模板** | 「明天下午三点开会」解析对了但会没建成。配置缺口：加 `parse → create` 模板，与票据入账同构（dispatcher 仓库） |

## 验收底线（沿用 dispatcher 侧的机械证据标准）

1. 每条断言有机械证据：测试、复现命令、哈希
2. 反例因该失败的那条而失败，放行路径也有测试盖
3. 静默失效比报错更糟（死配置、恒真判空）
4. 界面改动：构建绿 + 单测 + 模拟器过一遍
