- 建议工具：Pi
- 建议模型：`loomy/DeepSeek-V4.1-Flash`
- 依赖：T1（导入管线在同一批文件上）

## 目标
确认"导入完成后把陌生商户列表一次性发调度层归类"到底是接完了还是停在注释上，然后收口成可用功能。

## 上下文
- `feature/importer/ImportViewModel.kt` 里有一行 `// ---- 陌生商户批量归类（导入完成之后） ----`，但没有确证的调用链。
- 约定 7 写死过：**一次批量调用，不是 N 个任务**（`docs/product-roadmap.md` P1-c）。
- 调度层契约里已有对应能力；`DispatcherClient` 是六端点 + SSE。

## 具体要求
1. 先取证：grep 出这条链路的真实状态（有 UI？有调用？有测试？），在本任务卡末尾追加"现状结论"再动手。
2. 若未接完：一次批量把陌生商户名（去重、上限 N 条）发给调度层，返回的"商户→分类"建议以**可编辑列表**呈现，用户确认后才落库。
3. 网络失败/调度层超时时不得阻塞导入完成，"归类"是导入后的非阻塞追加动作。
4. 不动导入主流程的视觉。

## 禁止
- 不许把批量归类拆成 N 个单任务调用。
- 不许在用户未确认时自动改历史流水的分类。
- 不改现有测试用例；不引入新依赖。

## 验收标准
- `tools/build.sh :app:testDebugUnitTest` 全绿；新增用例覆盖：①去重与条数上限 ②网络失败不阻塞导入 ③未确认不落库。
- 任务卡末尾有"现状结论 + 证据（文件:行 / grep 输出）"。
- 报告给提交哈希与新增测试名。
