## 三个独立问题（都要处理，别只修一个）

1. **状态机把"节点 blocked / 空产出"算作成功。** `join_policy = all_or_fail` 应让"节点明确拒绝执行（blocked）"把任务落到 `failed` 或 `needs_clarification`，而不是 `succeeded`。要让客户端能区分「真入账了」和「模型说它没做成」。这条是主因。
2. **计划里节点的 `id` / `executor` 为 `None` 却能通过校验。** 校验器应当拒绝 `id` 为空的节点（`plan.py` 的节点校验），现在它连"节点的 id 是 None"都放过去了。
3. **兜底路由产出空 route id 还继续往下走。** `"LLM 选择的路由 '' 不在策略中"` 之后应直接以 `no_route` / `policy_violation` 收口（像 T4 hop② 第一次那样给出 422），而不是带着空路由走到拆解器再产出一个假计划。
