# T2 自动入账可撤销：LedgerRepository.void(journalId)

- 建议工具：**已改派 Pi + `kimi-k3-1`**（2026-10-24 用户定）
- 建议模型：`kimi-k3-1`——动的是账本核心不变量与留痕语义，改错会污染历史账
- **升级门**：改不动 / 失败两次 / 需要动 `JournalDraft` 的平衡校验语义 → 立刻升级 **Claude Code + Kimi-K3**（`ANTHROPIC_MODEL=Kimi-K3 claude -p ...`，scnet 端点）
- 依赖：无（可与 T1 并行，但同仓库串行，别同时派）

## 目标
给自动入账（高置信直接入账）配一个"事后可撤销"的真实能力，把 `UnavailableAutoEntryUndo` 那个占位换成能用的按钮。

## 上下文
- `core/ledger/LedgerRepository.kt`（417 行）现在**只有 `post`，没有 `void`**；`PostingDao` 的查询已排除 `VOID` 凭证（说明状态枚举早就留好了）。
- `docs/status-data-layer.md` 第八节「下一步」第一条就是这件事，且写清了正确做法：跟 `JournalStatus.VOID` 对齐，**作废留痕而非删行**，分录一并作废——删行会绕过凭证与分录的事务，留下孤儿分录。
- 界面侧现在的占位是 `UnavailableAutoEntryUndo`（"没能力就不渲染按钮"，这个判断本身是对的，别推翻）。

## 具体要求
1. `LedgerRepository` 增 `suspend fun void(journalId: Long)`：同一事务内把凭证置 `VOID` 并作废其分录；重复作废是幂等的；作废不存在的 id 要返回可区分结果而不是静默成功。
2. 作废后所有聚合查询（月度/分类/明细）立刻反映——依赖 `PostingDao` 已排除 VOID，补一条测试钉死这一点，防止将来有人改漏。
3. 界面把占位换成真实撤销入口，二次确认（这是不可逆动作）；撤销后列表项状态可见（作废留痕，不是消失）。
4. 不动其它界面视觉。

## 禁止
- 不许 `DELETE` 任何行来"实现撤销"。
- 不许改现有测试用例；不许引入新依赖。
- 不要把时间/金额精度从整数最小单位改成浮点。

## 验收标准
- `tools/build.sh :app:testDebugUnitTest` 全绿；新增用例覆盖：作废后聚合值回到原值、重复作废幂等、作废不存在 id 的失败路径、分录也一并作废。
- 报告：提交哈希、新增测试名、`void` 的事务边界写在哪、幂等怎么保证。
