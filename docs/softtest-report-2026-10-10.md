## A. 今天第 0 步新增（带实测证据）

### A1 🟢 根因 1 坐实：设置页加载是"白干的"，面板预热必然卸载重载一次
日志（连续窗口，同一进程 8231）：

```
08:43:27.733  Model loaded!                     ← 设置页点「加载模型」（第 1 次）
08:43:41.205  System prompt processed!          ← 设置页显示「已加载 · 可以生成了」
08:43:46.523  Unloading model and free resources...   ← 5 秒后，进首页开悬浮面板，warmUp 触发
08:43:46.622  Model unloaded!
08:43:47.974  Model loaded!                     ← 第 2 次
08:43:47.975  Sending system prompt...          ← 第 2 次解码系统提示（约 13s）
```

计数：`Model loaded!` ×2、`Unloading model` ×1、FATAL ×0。
**原因**：设置页用自己的 `SparkLlm` 加载（默认系统提示），`SparkSession` 要的是带科目表的
提示，引擎规定提示词只能紧跟加载设一次 → 功能页第一次用必须整轮重来。
详见 `docs/handoff-model-call-failure.md` 根因 1 / 修复方案 1。
**影响**：用户看到"已加载"，5 秒后引擎被卸载，面板还要再等一轮解码；设置页与功能页状态互不可见。

### A2 🟢 前端报错缺失，且文案与真实原因不符
面板发消息实测：`正在准备本机模型…` → 10s 后显示
**「这次没答上来（模型还没准备好或超时了）。可以点下面的入口，或者过一会儿再问一句。」**
而 logcat 里真实原因是：`AzhangChat: 无法解析模型输出: （暂无具体对话内容）`
——既不是"没准备好"也不是"超时"，是**模型输出不是合法 JSON**。
用户照文案等一会儿再问，结果一样（可稳定复现）。
对应 `AiFloatPanel.kt:354 FAILED_TEXT`（写死）与 `ensureReady`/`interpret` 只写日志。

### A3 🟢 模型对非记账输入吐非 JSON（输出质量问题，与昨天结论一致）
输入 `hello`（走 `【对话】` 模式），系统提示要求二选一（JSON 数组 / `{"reply":...}`），
实际输出：`（暂无具体对话内容）` —— 该串**不在代码里**（全仓 grep 0 命中），
是模型真输出。与昨天记录的"1.7B 会复述提示词、自言自语"同类。
提示词约束 / `DEFAULT_SAMPLER_TEMP=0.3` / 输出纠错（自动截取首个 JSON）都有调的空间。

### A4 🟡 根因 3（超时后引擎状态卡死）本机未复现 → 暂降级为观察项
今天实测加载 1.4s + 系统提示解码 13.5s，**合计约 15s**，远低于调用方预算
（面板 90s / 聊天 180s / 解析 240s），超时取消路径在这台模拟器上难触发。
留痕：2026-10-10，x86_64 模拟器，未复现；按 handoff 第七节第 0 步要求，
**真机验收时如复现则升级为最高优先级**，未复现则维持观察项。
